## Cross-references

| Reference | How it resolves | Edge |
| --- | --- | --- |
| the Notion page URL | URL → the decision page document | `OPS-410 → notion:page:<id>` |

This is the hop that makes the chain span two sources, and it is the one reference
that can silently fail. A URL reference matches the target's stored URL by **exact
string equality** (only trailing `.,;:!?` is trimmed), so:

1. Create the Notion pages first and run `lore sync`.
2. `lore trace "notion:page:<page id>"` — the URL printed under `anchor:` is the
   canonical one.
3. Paste exactly that string here. A "Copy link" URL from the Notion app may carry
   a `?pvs=…` query the API's own `url` field does not have, and then no edge forms.
4. `lore sync` again. A reference whose target was not yet indexed is retried at
   the end of every later sync round, so a stale ordering repairs itself — a wrong
   URL does not.

Deliberately **no** `INC-201` mention here. The demo has to prove that the path
from this ticket back to the incident runs *through Notion*; a direct ticket-key
reference would give the walk a shortcut and hide the cross-source hop.
